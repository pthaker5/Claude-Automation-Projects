# Showcase Projects

Portfolio artifacts, not homework. Each directory is **self-contained** (own README, code,
tests, data recipe) so it can be copied out of this repo and published independently later.

## The rigor markers (non-negotiable, every project)

A project is not "done" until its README has:

1. **Results plots at the top** — generated by code in the repo, one command to reproduce.
2. **Explicit in-sample / out-of-sample split with dates stated** — and nothing tuned on the
   out-of-sample period, ever.
3. **Transaction costs & realistic assumptions documented** — cost model, universe rules,
   rebalance timing (signal at close t → trade at open t+1, or equivalent stated convention).
4. **"Why this might not work / Limitations" section** — capacity, crowding, data biases,
   regime dependence, number of configurations tried. This section signals more maturity to a
   quant reviewer than any Sharpe ratio does.
5. **Tested code** — pytest suite passing; seeded randomness; pinned deps.

No fabricated numbers: a result appears in a README only after the code that produced it ran.
